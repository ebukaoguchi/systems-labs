# Instructor notes: Floating Point

**Origin of this module.** Floating point is taught in CIS 216 inside Lecture 003 (computer arithmetic), in the lecture's final section (slides 100–118 in the Fall 2026 deck), after integer addition, multiplication, and division. That material was deliberately *not* part of the ALU module ("Inside the ALU: Adders, Multipliers, and Dividers"), which stops at integers; this module is its planned follow-on. Like the ALU module, it is packaged from lecture material rather than converted from a lab deck, and the lecture deck itself is not published: it mixes instructor activities with textbook chapter material. Every worksheet, program, and the diagram here are original to this module. No textbook figures are used, and no completed in-class solutions from the lecture deck are reproduced; the worksheet numbers are new.

**Scope discipline.** Single precision only. Double precision (`.double`, `l.d`, register pairs, the `.d` instructions) is named in one sentence in class and left as an extension: the field layout is the same idea at 11/52 bits, and students who own the single-precision format can read the double format unaided. Special values (zero, infinities, NaNs, denormals) are likewise a discussion point, not a milestone: the worksheets stay with normalized finite values, where the formula always works.

**The 0.1 moment.** Worksheet A3 is the module's most valuable ten minutes. Students discover the repeating binary fraction themselves, then check `float_bits.c`'s output and see the rounded pattern 0x3DCCCCCD. Resist explaining it first. The follow-up question that lands best: "Your calculator says 0.1 + 0.2 is not 0.3. Whose fault is that, the addition's or the representation's?" (The representation's: neither operand was exact before the addition began.)

**QtSpim practicalities.** QtSpim prints syscall 2 values in a fixed format with trailing zeros; grade the values, not the formatting, and tell students so in advance (worksheet Part D says it too). The bit-pattern print (syscall 34) shows no `0x` prefix and no leading zeros in QtSpim; the self-check's "40f00000" is the full eight digits because 7.5's pattern happens to start with 4. If students test a value whose pattern starts with 0 (say 0.5, 0x3F000000), QtSpim prints fewer digits; that is a display property, not an error.

**Verification.** `floating_point.asm` was executed before publication: outputs are 10.0, 5.0, 18.75, 3.0, the message "a is greater than b", and the bit pattern 40f00000, exactly as the worksheets predict. `float_bits.c` compiles clean under `gcc -std=c11 -Wall -Wextra`, and every worksheet answer in the self-check was produced or confirmed with it (5.75 → 0x40B80000; −12.25 → 0xC1440000; 0.1 → 0x3DCCCCCD; 100.5 → 0x42C90000; 12.5 → 0x41480000).

**Extensions for strong students.** (1) Add a double-precision section to the program and compare field widths. (2) Find the smallest positive float the class can construct, then discuss denormals. (3) Compute 0.1 + 0.2 in the program, print the bits of the result, and decode them by hand: whose worksheet skills explain the outcome?
